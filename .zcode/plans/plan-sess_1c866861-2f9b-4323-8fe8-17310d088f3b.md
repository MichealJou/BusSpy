# 烧录后端 Rust 化 — 第一阶段：SWD 主链路 PoC

## 目标

用 `probe-rs` 验证能否替代 pyOCD 完成 SWD 烧录/擦除/读芯片，覆盖你的核心器件矩阵，为后续全量迁移提供决策依据。本阶段**只加依赖 + 写独立 PoC + 硬件验证**，不改动现有 Tauri 命令和 Python 后端（两者继续共存，互不影响）。

## 本阶段范围

### 1. 加依赖
在 `apps/desktop/src-tauri/Cargo.toml` 增加：
- `probe-rs`（feature 开 `stlink`、`cmsis-dap`、`jlink`，实际 feature 名以官方文档为准）
- 可能需要的辅助：`object`（解析 HEX/BIN，替代 Python 的 intelhex）

### 2. 写独立 PoC（`apps/desktop/src-tauri/examples/flasher_poc.rs`）
一个命令行示例程序，**不接 Tauri**，参数 `probe-id target filePath [--erase-only] [--info]`，跑通以下能力并把结果打印成与前端一致的 JSON（`FlashProbeInfo` / `FlashChipInfo` 同构）：

- **枚举探针**：`probe-rs` Lister 列出 identifier/protocol/vendor/product，输出 `{id, vendor, product, uniqueId, protocols}`，与现有 `probe_scan.rs` 的 rusb 方案做对比
- **连接 + 自动识别 target**：读 `DBGMCU_IDCODE 0xE0042000` → `& 0xFFF` → 查 `STM32_DEVID_TARGETS` 映射表（32 条，从 flash.py 平移）→ 得到 target 名
- **整片擦除**：等价 `flash.erase` 的 chip erase
- **烧录**：加载 BIN/HEX → flash 算法（FLM）→ 擦除 → 编程 → 校验，输出 `{ok, verified}`；烧录后 `reset + halt + resume`（复刻 flash.py 行为）
- **读芯片信息**：读 flash 大小（第一个 flash region）、core id（DP IDR）、uid（三个地址 `0x1FFF7A10`/`0x1FFFF7E8`/`0x1FFF7590` 依次读 3 个 32-bit 字），输出 `{flashSize, chipId, coreId, uid[], target, suggestedTarget}`

### 3. 硬件验证（需你配合）
我保证代码编译通过（`cargo build --example flasher_poc`），但**真实烧录验证需要你在本地有探针+板子的环境跑**，我会给出运行命令。验证矩阵：
- 探针：ST-Link V2/V3、J-Link、CMSIS-DAP 各至少一类
- 器件：STM32F407/F103 等核心 STM32 + **GD32（重点风险项）**

### 4. 产出决策报告
PoC 结果决定后续路径：
- 若 STM32+J-Link 全通过 → 进入阶段 2 全量迁移
- 若 GD32 或某类探针不通过 → 明确缺口，评估「probe-rs 为主 + 特定器件保留 pyOCD 回退」的混合方案

## PoC 之后的全景路线（本次不实施，仅列出方向）

- **阶段 2**：串口 ISP（AN3155）+ SN 编解码，纯 Rust 重写（不依赖 probe-rs，风险最低）
- **阶段 3**：SWD 主链路正式接入 Tauri command，替换 `flash_program/erase/read_chip_info/list_probes` 的 Python RPC 转发；重写 FLM 提取（zip + .pdsc XML 解析，Rust 端目前空白）；`target.list`/`pack.list`/`pack.import` 改为本地实现
- **阶段 4**：量产模式后台轮询线程 Rust 化
- **阶段 5**：删除 Python 后端、RPC、bootstrap、sidecar 打包逻辑，更新 CI

## 关键风险（PoC 重点验证）

1. **GD32**：probe-rs 无 stm32-data 覆盖，需 GD32 厂商 Pack 的 FLM + 额外 target 描述，是最大不确定性
2. **J-Link**：官方称支持全变体，需实测稳定性和协议细节
3. **FLM 加载机制**：probe-rs 从 Pack 加载 flash 算法的路径与 pyOCD 是否一致
4. **target 描述来源**：stm32-data 内置 vs 需从 Pack 用 target-gen 生成
